| M-02 | util `bc/sub-genbuildinfo.go` (`clog BC gen buildinfo`) | A prod build never checks that `releases.yaml` agrees with git, so a tag cut without its history entry (step 1 of *Cutting a release*) ships silently. Add one canonical check in `gen buildinfo`, the single place every build already asks git for its version: path from `kfg.ReleasesPath()` (the working directory's file, **not** the copy `main.go` embeds). No file → `slog.Info`, carry on: releases.yaml is optional history. File present in **prod** → the release tag must have an entry, it must be the newest, with `build: prod`; otherwise refuse, naming the tag and the file. Dev builds do not check. Constraints: gate on **prod mode, not on `--format version`** — `bc-golang` calls it with `--format ldflags` then `--format version` (`embedfs/konfig.yaml:730-733`), and a check tied to one format would let the other through; stdout stays the single value (`$(…)` callers), logs go to stderr; the help's "releases.yaml is history and is not read" becomes "…is not a source of the version; a prod build checks it agrees". git stays the instruction; the file only has to agree. Lands in util (tag `bc/vX.Y.Z` per module), then a pin bump here. |
